# Campaign115：一次请求的跨崩溃保护

Campaign115 的 `limit_list_d` 验收 runner 已关闭一个重复调用风险：旧实现只在进程内持有锁，如果 provider 请求完成后、成功或失败记录写入前崩溃，后续 `plan` 可能再次允许请求。新实现会在读取凭据和 provider 访问之前，以独占、禁止跟随符号链接、0600、文件与目录双 `fsync` 的方式写入一次性 attempt intent，并固定同一运行的设备号和 inode。该标记永不由 runner 删除；无论崩溃发生在请求之前还是之后，后续公共 plan 都会拒绝第二次尝试。

24 项适配器与 runner 定向测试、59 项 Campaign113 至 Campaign115 联合回归均通过。模拟首次 provider 调用失败后，即使移除失败记录，持久化 intent 仍阻止第二次 provider 调用。真实零网络 plan 显示 v3 运行时绑定、一次性 intent 可用、日历、4592 只点时可买股票、`.env` 安全属性和 Token 存在性全部通过；唯一 blocker 仍是用户尚未明确确认当前账户已有 5000 积分。真实 provider 请求、attempt intent、成功清单和失败记录均为 0。

本次仅加固单次验收的跨崩溃语义，没有改变来源、公式、方向、日期、门槛、特征库或台账计数。完整定义仍为 141，数值比较器仍为 134，累计历史研究尝试仍为 858，历史收益读取试验仍为 302。Candidate49 两本前瞻账本不变，未启动第二个前瞻候选。
