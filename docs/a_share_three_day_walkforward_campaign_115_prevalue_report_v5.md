# Campaign115：可审计的一次请求状态机

Campaign115 的 `limit_list_d` 验收 runner 现在会把一次请求的关键阶段写入同一个私有、唯一 inode、永不删除的 JSONL attempt journal。journal 在读取凭据前创建并同步到磁盘；在可能进入 provider 函数前先同步记录“请求已获准且可能开始”，响应返回后只记录行数，不保存原始响应；失败只记录归一化失败码，不保存 Token、Token 哈希或 provider 明文错误。这样即使进程在终态清单发布前崩溃，也能区分“仅消费尝试”“请求可能已进入”“响应已返回”和“终态发布已开始”，同时仍禁止第二次请求。

成功和失败 JSON 改为独占、禁止跟随符号链接、0600 临时文件，完整写入并 `fsync` 后原子替换，再同步父目录；因父目录同步失败而无法证明发布完成时，会移除刚发布的记录并保持失败关闭。factor Parquet、staging 目录和最终目录父级也在相应发布点同步。28 项适配器与 runner 定向测试、63 项 Campaign113 至 Campaign115 联合回归均通过，包含部分写重试、目录同步失败回滚、provider 入口前 journal 证据、模拟失败阻止第二次请求及模拟成功发布。

真实零网络 plan 的 v4 运行时绑定、一次性 journal 可用性、日历、4592 只点时可买股票、`.env` 安全属性和 Token 存在性均通过；唯一 blocker 仍是用户尚未明确确认当前账户已有 5000 积分。真实 provider 请求、attempt journal、成功清单、失败记录和 factor frame 均为 0。

本次没有改变来源、公式、方向、日期、门槛或特征库。追加式台账 v6 补记了上一轮一次裸 `python` 不在 PATH、在 pytest 收集前以 127 退出的验证命令；它未读取研究值，也未触发 provider。Campaign115 尝试数因此为 6，其中基础设施失败 4；累计历史研究尝试为 859，历史收益读取试验仍为 302。完整定义仍为 141，数值比较器仍为 134。Candidate49 两本前瞻账本不变，未启动第二个前瞻候选。
